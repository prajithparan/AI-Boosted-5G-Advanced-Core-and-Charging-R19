## ADR-0465: Closed ADRs: status verified against origin/main, archived under docs/decisions/archive/

**Date:** 2026-10-06. **Status:** Accepted (user-directed: cross-check ADR status against what was actually pushed, update it, and move the closed ones).

**Context.** `docs/decisions/` holds 418 ADRs. No ADR carried a `Closed` status, so finished work and open work were indistinguishable in the index. "Accepted" records that a decision was made, not that its work landed.

**Decision:** An ADR is **Closed** when (1) at least one commit on `origin/main` cites it, and (2) its text contains none of the open-work markers (disclosed gap, not yet, deferred, stub, TODO, not started, remaining, open question, follow-up, blocked, simplif, not conformant, partial), and (3) a human review of the candidates found no ADR whose own status says it is temporary, in progress, amended or open. The first run closed 73 of 418; ADR-0006, 0292, 0420, 0422, 0454 and 0456 passed (1) and (2) but were kept open by (3). Closing prefixes `Closed (work pushed; last citing commit <hash> on origin/main, <date>).` to the existing status and leaves the old status text in place. Closed ADRs move with `git mv` to `docs/decisions/archive/`, and `DECISIONS.md`, `INDEX_DETAIL.md` and `_order.json` point there. Tooling: `scripts/docs/close_adrs.py`; `adr_lib.adr_files()` and `check_adr_index.py` read both directories. Reproducible: re-run the cross-check, review the list, run `close_adrs.py LIST`, then `check_adr_index.py`.

**What this does not prove.** A citing commit shows work was pushed, not that it is complete or correct; the ADR's own text is what says whether gaps remain, and the marker scan is a keyword heuristic, not a reading. 322 ADRs were left open because their text still mentions a gap or simplification, many of which are probably resolved in later ADRs; those were not individually reviewed. `Closed` is therefore "pushed and no open-work wording", not an audit.

**Consequence for the split guard.** `_order.json`'s `original_sha256` was a one-time proof that splitting `DECISIONS.md` lost nothing; any status edit changes the text, so it can no longer gate. It is kept as a record, the check was removed from `check_adr_index.py`, and `split_commit` (0530e4f) names the commit that reproduces the originals. ADR-0464's status-note edit (6d97077) had already broken that check unnoticed, because nothing in CI runs it.

**Rejected alternatives.** (a) Re-record `original_sha256` after every edit: turns a proof into a rubber stamp. (b) Forbid all edits to split ADRs so the guard keeps passing: ADRs would be unable to record that their gap was closed. (c) Delete closed ADRs: loses the decision record the index points to. (d) Close by keyword scan alone with no human pass: it would have closed ADR-0006 ("Accepted (temporary)") and ADR-0456 ("one open TSan finding").
