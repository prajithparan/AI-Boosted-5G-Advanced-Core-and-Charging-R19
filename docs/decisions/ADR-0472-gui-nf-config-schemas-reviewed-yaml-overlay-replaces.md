## ADR-0472: GUI NF-config schemas: reviewed YAML overlay replaces example-inferred subtrees (PCF policy counters creatable with any session rule id)

**Date:** 2026-10-09. **Status:** Proposed.

**Context.** ADR-0425 derives each component's GUI configuration schema from its `config/<nf>.json` and source. For a nested object it can only infer the shape of the current values, so it marks the subtree "map-vs-struct meaning unverified; new keys refused until reviewed" (`x-review`). For `config/pcf.json` `policy_counter_actions[].smPolicyDecision`, which carries a TS 29.512 `SmPolicyDecision`, that produced `sessRules` with exactly one allowed key, `spending-limit-rule`, and `additionalProperties: false` throughout. In TS29512_Npcf_SMPolicyControl.yaml `sessRules` is a map (`additionalProperties: $ref SessionRule`, keyed by `sessRuleId`). So an operator could not create a policy counter with any other session rule id in the GUI, which is the user's 2026-08-16 requirement (a GUI-creatable `policyCounterIds` model, ADR-0328). Verified before the change: a new counter with rule id `my-rule` was rejected by the old schema (1 error) and is accepted by the new one (0 errors); the current config/pcf.json validates against the new schema (0 errors).

**Decision:** `gui/schema-gen/overlay-nf-config.json` lists reviewed replacements, `{nf: {"key[].sub": "<yaml file>#<pointer>"}}`. `derive_nf_config_schemas.py` inlines the named 3GPP schema (all `$ref`s across files, descriptions and examples dropped, reference cycles cut to an open object) and records the source as `x-yaml`; the example-inferred review note for that subtree is removed; an overlay naming a path absent from the config is a hard error. One entry exists: `pcf` `policy_counter_actions[].smPolicyDecision` -> `SmPolicyDecision` (48 KB, 7 YAML files). `gui_schema_checks_reject_drift` gained a case asserting the schema is a map derived from that YAML; it fails against the old schema (checked). Only `pcf.schema.json` changed; the other 33 schemas are byte-identical.

**Not done / disclosed.** (1) The remaining fields of the policy-counter item (`policyCounterId`, `currentStatus`) are still example-inferred (one review note remains). (2) Other NFs with nested 3GPP-typed values may have the same defect; they were not audited, and no overlay exists for them. (3) The JSON Forms vanilla renderers do not edit `additionalProperties` maps with a native control; whether the form lets an operator add a new rule-id key has NOT been tested in a browser. The schema now permits it; the editing UX is unverified. (4) The web bundle grew from 555 kB to 602 kB. (5) `anyOf`/`oneOf` in the inlined YAML schemas are passed through unchanged.

**Rejected alternatives.** Hand-editing `pcf.schema.json` (it is generated; the next regeneration would revert it, and the drift check would fail). Setting `additionalProperties: true` on the inferred subtree (validates nothing, and loses the YAML shape). Inferring map-vs-struct from key names (a guess; the YAML states it).
