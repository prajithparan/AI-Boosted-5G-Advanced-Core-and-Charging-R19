## ADR-0469: CI: skip build and sanitizer jobs for docs-only changes; lint first, sanitizers only after build passes

**Date:** 2026-10-07. **Status:** Accepted; edited in `ci.yml` locally, NOT yet pushed or run, so the saving is an estimate and the `changes` job and the `needs` graph are untested in CI.

**Context.** Timings of the last green full run (37479623570, a push to main): the four jobs run one after another on the single lab runner and sum to 157 min (lint 37, asan-ubsan 42, tsan 44, build 34); the test steps are 24 + 29 + 29 min of that, because the same 927 tests run three times. This repository updates documentation on every push (standing rule), so many pushes change only Markdown and still pay the full run. Previously `lint` and the sanitizers had no ordering, so a failing PR could spend over an hour in sanitizers before a one-minute formatting failure was reported.

**Decision:** (1) New `changes` job on `ubuntu-latest` (so it never queues behind the lab runner) diffs the push or PR against its base and sets `code=false` only when every changed file is under `docs/`, is a `.md` file, is `LICENSE`, or is an issue/PR template. `build` and `sanitize` run only when `code=true`. Doubt means `code=true`: schedule and manual runs, a missing or unreachable base commit, and a failed diff. (2) `lint` stays unconditional because it also runs `tools/diagrams/check_readme_sync.py` (README diagram sync). (3) `build` needs `lint`; `sanitize` needs `lint` and `build`, so the cheap checks report first and the ~85 min of sanitizer tests are not started for a run that already failed. Job names are unchanged.

**Not done / limits:** untested in CI. A skipped job reports as skipped, which GitHub treats as passing for required checks; this should be confirmed once branch protection is configured. The docs-only rule trusts that nothing outside `lint` reads documentation at test time (searched `tests/` and the CMake files: only message strings mention docs, no test opens a doc file). A docs-only run still runs `lint`'s setup (vcpkg, configure), several minutes, not the full run. On schedule runs `build` now waits for the 4.5 to 5.5 h full-sweep `lint`, which on a single runner does not change total time. This does not shorten a code run: the jobs still run serially and the tests still run three times (profiling the slow tests and reducing the TSan pass are separate tasks).

**Rejected alternatives.** Workflow-level `paths-ignore`: a skipped workflow leaves required checks pending, which would block merging docs PRs once `main` is protected. Running `changes` on the self-hosted runner: it would queue behind long runs. Skipping `lint` for docs-only: it checks the README diagram, which docs changes can break.

**Correction (2026-10-08).** On a `pull_request` event the `changes` job diffs the whole PR against its base (`PR_BASE`), not the last push, so the skip applies only when the entire PR is docs (or on a push to `main`). Observed on run 37734162956: a README-only push to PR #2 still ran build and both sanitizers because the PR also contains code. A per-push skip was rejected: it would let a docs-only follow-up go green without re-testing the earlier code commits on that head, the same false-green hole ADR-0468 closed for lint.
