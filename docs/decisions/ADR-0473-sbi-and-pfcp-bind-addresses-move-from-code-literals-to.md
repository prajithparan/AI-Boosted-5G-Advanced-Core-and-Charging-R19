## ADR-0473: SBI and PFCP bind addresses move from code literals to config/<nf>.json (sbi_bind_address, pfcp_bind_address)

**Date:** 2026-10-09. **Status:** Proposed.

**Context.** Standing user rule (reaffirmed 2026-10-09): ports, IPs and every other parameter that can change per deployment live in `config/<nf>.json`, never as a literal in a `.cpp`. ADR-0357 moved the ports; an audit on 2026-10-09 found the bind ADDRESS still hardcoded: 26 of the NFs under nfs/ constructed their SBI server with a literal `"0.0.0.0"` (`Server server(ioc, "0.0.0.0", port, ...)`) and logged it, and the UPF bound PFCP with `udp::v4()` and logged `0.0.0.0`. The metrics bind address was already a config value (`metrics_bind_address`), which made the omission easy to miss.

**Decision.** Each of the 26 NFs reads `sbi_bind_address` with `nf_config::require<std::string>`, exactly like its `metrics_bind_address` (with env override `<PREFIX>_SBI_BIND_ADDRESS` where that NF's metrics address has one), and passes it to the server and the listen log line. The UPF also reads `pfcp_bind_address` (env `UPF_PFCP_BIND_ADDRESS`), parses it as IPv4 (an unparsable value is fatal at start with a clear message) and binds PFCP to it. The shipped value is `"0.0.0.0"` in every `config/<nf>.json`; it is `require`d, not defaulted in code, so a config without the key fails at start instead of silently binding every interface. Copies of an NF config were updated in the same change: `deploy/docker/li-admf.compose.json`, `deploy/helm/upf/values.yaml` (both keys). The integration tests that build an li-admf config start from `config/li-admf.json`, so they inherit the key. The GUI schemas were regenerated (26 now carry `sbi_bind_address`, UPF also `pfcp_bind_address`); the derive check and drift tests pass.

**Verification.** Each of the 26 changed `main.cpp` files was compiled syntax-only against the real compile database (results in the commit message and the session log). NOT run: any integration test or container, because the self-hosted CI runner shares loopback ports with local tests and was busy; a runtime check that every NF still starts with the new key is therefore still owed, and CI's Test step is the first one that will run it.

**Not changed, on purpose.** The UPF's loopback self-wake of its own PFCP socket at shutdown (`127.0.0.1`, or the configured address when bound to a single one) is internal plumbing, not a deployment parameter. The LI POI `x1_bind_address` already comes from config; its `"0.0.0.0"` fallback in code (AMF, SMF, UPF) is redundant because all three shipped configs set it, and was left. Only `nfs/*/src/main.cpp` server construction was audited: other binaries (`gui/bff`, `bss/*`, `tools/*`) were not checked for bind-address literals and may need the same change. Helm charts other than the UPF carry no config copy.

**Rejected alternatives.** A default of `"0.0.0.0"` in code (it is the literal the rule forbids, and hides a missing key). One shared key in `nf_config` for all NFs (each NF owns its config file; a shared key would make a per-NF override impossible). Binding a hostname (the servers take an IP).
