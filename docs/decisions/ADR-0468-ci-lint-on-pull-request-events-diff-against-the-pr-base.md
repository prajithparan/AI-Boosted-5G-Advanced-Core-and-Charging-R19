## ADR-0468: CI lint on pull_request events: diff against the PR base instead of a full clang-tidy sweep

**Date:** 2026-10-07. **Status:** Accepted; the change is in `ci.yml` locally, NOT yet pushed or run in CI, so its effect is unverified.

**Context.** CI run 37559833729 (PR #2) ended `cancelled`: the `lint` job ran 03:13:51Z to 09:14:46Z, i.e. the 6 h GitHub job limit (`ci.yml` sets no `timeout-minutes`), and the runner log shows a cancellation request, no OOM kill (kernel and systemd-oomd logs empty, memory PSI ~0). The same job took 37 min on the push run 37479623570. Cause, read from `ci.yml`: ADR-0371 limits a push's clang-tidy to the files changed since `github.event.before`, but that field exists only on `push` events. On `pull_request` it is empty, so the script's `[ -z "$BEFORE" ]` branch ran the full sweep over every `.cpp` under libs/ and nfs/ (233 files today; ADR-0371 measured 4.5 to 5.5 h for the full sweep). Every PR lint run was therefore either very long or cancelled. The earlier statement that the cancellation looked like a memory kill was wrong.

**Decision:** For a `pull_request` event with no `before`, use `github.event.pull_request.base.sha` as the base: fetch it shallow (`--depth=1`, a diff only needs the two trees) and run the existing changed-file diff against the PR's merge commit. Push, schedule and `workflow_dispatch` behaviour is unchanged. A PR that changes no `.cpp` now lints nothing and exits 0 (currently true for this branch's committed diff against origin/main: 0 of 233 files).

**Not done / limits:** not run in CI yet. A PR that changes a shared header lints only its changed `.cpp` files, not their includers, the same limitation ADR-0371 accepted for pushes. Added in the same change (also unpushed and unrun): per-job `timeout-minutes` of 240 for `build` and both `sanitize` legs, and for `lint` 90 on push/PR but 360 on schedule/workflow_dispatch, because the weekly full sweep legitimately takes 4.5 to 5.5 h and a flat 90 would kill it. The 240 and 90 are chosen from measured 34 to 44 min runs plus headroom, not from a cold-cache measurement. The weekly full sweep remains the only whole-tree lint.

**Rejected alternatives.** Raising the job timeout: the 6 h limit is GitHub's maximum for hosted and the sweep still takes 4.5 to 5.5 h. Skipping lint on PRs: the PR is where outside contributions get checked. `run-clang-tidy` with a diff: changes which files are analysed (ADR-0371 reasons).

**First PR run with the fix (run 37629450250, 2026-10-07):** `lint` analysed the 2 changed `.cpp` files, not the tree, and still took 28.6 min: clang-tidy on `nfs/upf/src/main.cpp` alone took about 32 min locally (measured, exit 0). The job failed for an unrelated reason in the same change: the new `advertised_address` files used `std::expected`, which `clang-tidy-18` cannot parse (`no template named 'expected' in namespace 'std'`); GCC builds and tests did not catch it. Switched to `tl::expected`, the idiom of the other 42 files; local clang-tidy on both files then exited 0. The `ci-auto-retry` workflow reran the failed job, which cannot pass without a new push.
