## ADR-0467: Contributor model: CLA, one-area-per-PR, approval for all outside contributors, org move deferred

**Date:** 2026-10-07. **Status:** Accepted for the rules text and the one setting already applied; the CLA, `CODEOWNERS`, area-label CI check, `bootstrap.sh`, branch protection, hosted-runner fork CI and the organization move are NOT done (listed below).

**Context.** The maintainer plans to open the repository to outside contributors, organised by domain area (core, provisioning, charging/BSS, products and catalog, security/LI, NWDAF/analytics, automation, GUI), while keeping the final merge and versioning. `.github/CONTRIBUTING.md` was stale (said "~100 ADRs", told contributors to edit `docs/DECISIONS.md` by hand, no area rule, no mention of the CLA, the compose config mount or docs-current). Checked on 2026-10-07: `main` has no branch protection, there is no `CODEOWNERS`, the repository is public and owned by a user account (so no runner groups), the only CI runner is a self-hosted lab machine, and the fork-PR approval policy was `first_time_contributors`.

**Decision:** (1) A Contributor License Agreement, not a DCO, because ADR-0049 keeps a commercial option open and a CLA is the only way to keep the right to relicense. Text and signing bot are not written yet. (2) One area per PR, with the area-to-path table in CONTRIBUTING.md as the source of truth; platform libraries are maintainer-only; cross-area work needs the maintainer's `cross-area` label. (3) Fork-PR approval set to `all_external_contributors` (applied via the GitHub API and read back on 2026-10-07). (4) The organization move, which is the only hard barrier keeping fork PRs off the self-hosted runner, is deferred until just before outside contributors are invited. (5) `.github/CONTRIBUTING.md` rewritten; items not yet in force are marked "(planned)" in the text rather than described as active.

**Not done, in the order intended:** CLA text + bot; `CODEOWNERS` and a path-labeler plus a CI check rejecting multi-area PRs; `scripts/bootstrap.sh` (pinned, checksum-verified dependency installer, with an assistant-side check that asks before installing); a shared vcpkg binary cache; branch protection on `main`; fork PRs on GitHub-hosted runners; the GitHub organization with a runner group limited to `refs/heads/main` workflows. Hosted runners are not a boundary on their own: a `pull_request` run uses the workflow file from the PR, so a fork can name a self-hosted runner in its own `runs-on`; only the approval setting and the org runner group prevent that. ADR-0363 records that the old hosted runners (2 vCPU, 7 GB) took 1.5 to 2 hours per run; fork CI speed is unmeasured. The proposed convention that the maintainer may renumber a colliding ADR at merge is new here and not yet exercised. Area-table paths for `agents/`, `simulators/` and `specs/` are unassigned on purpose, and where Consumer and Enterprise offers are defined in the repo has not been verified.

**Rejected alternatives.** DCO only: lighter for contributors but cannot support relicensing. Conditional `runs-on` in `ci.yml` as the fork-PR protection: not a boundary, see above. Deferring only the CONTRIBUTING rewrite: it was wrong today (broken advice on ADR editing), so it is fixed now. Making the organization move now: costs a one-time disruption (URL changes in docs, runner re-registration) and protects nothing while no outside PRs exist.
